# نظام المقهى — نقطة بيع ومراقبة المخزون

نظام لمقهى واحد في تونس، يتكوّن من جزأين:

- **شاشة الطلبات للتابلت (`/pos`):** "عمياء"، أي لا تعرض أي سعر أو مجموع أو مخزون، وتعمل بدون إنترنت.
- **لوحة المالك (`/admin`):** محمية بكلمة سر وتحقق بخطوتين.

المرجع الكامل هو [CAFE_POS_SPEC.md](CAFE_POS_SPEC.md).

---

## 1. التشغيل المحلي (على حاسوب في المقهى)

يتطلب **Node.js 20 أو أحدث**.

```bash
npm install
npm run build
npm start
```

ثم افتح `http://localhost:3090/admin`:

1. أنشئ حساب المالك.
2. فعّل التحقق بخطوتين: امسح رمز QR بتطبيق Google Authenticator.

في الوضع المحلي:
- **قاعدة البيانات** هي Postgres مدمجة (PGlite) محفوظة في `./data/db`.
- **المفاتيح السرية** تُنشأ تلقائياً في `./data/secrets.json`.

> **انسخ مجلد `data/` احتياطياً كل يوم** (قرص خارجي أو سحابة). ضياعه = ضياع كل البيانات.

> **الكاميرا لمسح QR تتطلب HTTPS.** عبر شبكة المقهى المحلية بـ `http://192.168.x.x` لا تعمل الكاميرا، لكن إدخال رمز التذكرة يدوياً يعمل. للكاميرا استعمل الاستضافة السحابية (الخيار 2)، أو شهادة HTTPS محلية.

## 2. الاستضافة السحابية (موصى بها): Vercel + Neon

1. أنشئ قاعدة **Neon Postgres** في منطقة **EU (Frankfurt)**، وفعّل PITR.
2. ارفع المشروع إلى GitHub واربطه بـ **Vercel**. الخطة المدفوعة مطلوبة للاستعمال التجاري ولـ Cron كل ساعة.
3. أضف متغيرات البيئة (انظر `.env.example`):
   - `DATABASE_URL`: رابط Neon (pooled).
   - `SESSION_SECRET` و`TOTP_ENCRYPTION_KEY` و`CRON_SECRET`: أنشئ كل واحد بالأمر:
     ```bash
     node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
     ```
   - `TELEGRAM_BOT_TOKEN`: اختياري، للتقرير اليومي.
4. انشر المشروع. جداول قاعدة البيانات تُنشأ تلقائياً عند أول طلب، من مجلد `drizzle/`.
5. `vercel.json` يشغّل مهمتين تلقائياً:
   - الفحوصات كل ساعة.
   - التقرير اليومي على تيليغرام الساعة 07:00 بتوقيت تونس.

> **لا تغيّر `TOTP_ENCRYPTION_KEY` بعد التشغيل.** هذا المفتاح يشفّر سر التحقق بخطوتين ورموز التذاكر. إذا تغيّر لن تستطيع إعادة طباعة التذاكر القديمة، وستحتاج لإعادة تفعيل التحقق بخطوتين.

## 3. تجهيز التابلت (Fully Kiosk Browser PLUS)

1. **في لوحة الإدارة ← الأجهزة:** أنشئ رمز ربط. الاسم مثلاً `T1`، والرمز صالح 10 دقائق.
2. **على التابلت:** افتح `https://<عنوانك>/pos` وأدخل الرمز المكوّن من 8 أرقام.
3. **إعدادات Fully Kiosk:**
   - Start URL هو `/pos`.
   - كلمة سر للخروج (Kiosk PIN)، وهي منفصلة عن كلمة سر الإدارة.
   - التشغيل عند الإقلاع، والشاشة دائماً مضاءة.
   - إخفاء أشرطة النظام.
   - تعطيل: السحب للتحديث، التكبير، تحديد النص، لقطات الشاشة، ومسح بيانات التطبيق.
   - السماح بالكاميرا.
   - منع تغيير الساعة والإعدادات.
4. افتح `/pos` مرة واحدة والإنترنت متصل. بعدها يعمل التطبيق حتى بدون إنترنت، والطلبات تُحفظ على الجهاز وتُرسل تلقائياً عند عودة الاتصال.

## 4. أول خطوات الإعداد في لوحة الإدارة

1. **المخزون:** أضف كل المواد مع مخزونها الافتتاحي وحدّها الأدنى. الوحدات: وزن بالكغ، حجم باللتر، أو بالقطعة. أمثلة: بن، جيراك، معسل بكل نكهة، فحم، حليب، سكر، شاي، ماء، قزوز، كرواسون، عصير…
2. **المنتجات:** لكل منتج حدّد السعر والوصفة. في الوصفة تكتب لكل مادة الإنتاج المحسوب والإنتاج الحقيقي، أمثلة:
   - القهوة: 80 و90 فنجان/كغ.
   - الجيراك الكبير: 15 و16 شيشة/كغ.
   - الحليب في الكابوسان: كمية بالمل.
   - القارورة: 1 قطعة.
3. **الشيفتات:** حدّد المسؤول الافتراضي لكل شيفت، وعدّل الجدول عند التغيير.
4. **الزبائن والتذاكر:** أضف الزبون، ثم أصدر له ورقة تذاكر واطبعها.
5. **عند كل تسليم شيفت:** شخص الثقة يكتب على ورقة المخزون المتبقي والكاش وعدد أوراق التذاكر، مع وقت الجرد. أنت تدخلها في صفحتي:
   - **الجرد:** صفحة الجرد.
   - **الكاش والتذاكر:** صفحة الشيفتات والكاش.

## 5. الاختبارات

```bash
npm test
```

52 اختباراً تغطي:
- حدود الشيفت ويوم العمل.
- حساب المال والمخزون بأعداد صحيحة.
- تحليل الهامش.
- نسخ الأسعار والوصفات.
- المزامنة: التكرار، الفجوات، سلسلة التحقق، وتصحيح الساعة.
- التذاكر: الاستعمال المزدوج، السقف، والكريدي.
- الإلغاء.
- الكاش والأرباح.
- التنبيه المبكر قبل نفاد المخزون.
- غياب الأسعار من التابلت.

## 6. هيكل المشروع

| المسار | المحتوى |
|---|---|
| `src/server/` | منطق الأعمال على الخادم: الطلبات، المزامنة، المخزون، التذاكر، المالية، المصادقة، التنبيهات |
| `src/pos/` | تطبيق التابلت (IndexedDB، المزامنة، الماسح) |
| `src/app/admin/` | صفحات الإدارة (Server Components + Server Actions) |
| `src/app/api/` | واجهات الجهاز (`sync/push`، `sync/config`، `pos/ticket-check`، `device/pair`) و cron |
| `src/db/schema.ts` | قاعدة البيانات |
| `drizzle/` | ملفات الترحيل (migrations) |
| `tests/` | الاختبارات |

بعد أي تغيير في `schema.ts` شغّل:

```bash
npm run db:generate
```
